# Session log - 7 October 2026

Short session, done from ScaleView for REAPER's repository. ScaleView Pro's
chord reader had two changes made and measured there, and the copy here was
brought up to date with them. The user asked that **ScaleView Pro be the
reference**, not the VST3/CLAP plugin.

## What changed

`ms_theory.lua`'s reader block (`CORE_RANK` through `analyse`) was diffed
against Pro at `e31a6e8` first and was identical, so it was replaced with Pro's
block at `f9e2691` verbatim. The tiebreak in `nameChord` was edited to match
Pro's `detectChord`:

- **An altered dominant on its own root keeps its alterations.** C7#5b9 read
  `A#min9b5/C`; it reads `Caug7b9`. Likewise `C7b5b9`, `C7b5#9`.
- **A draw goes to the reading that needs no slash**, after the key and before
  the commoner quality. C D G Bb over C read `GminAdd11/C`; it reads `C7sus2`.

Eight tests were added to `test_theory.lua` and six of them failed on the old
copy before the change. Every suite passes after it.

## How it was checked

`nameChord` against `ScaleView Pro.lua` run through Pro's own `tools/runner.lua`:
60,212 voicings - the 17,688-voicing sweep, every one- and two-note chord, and
all 37,106 distinct sonorities of music21's core corpus with their doublings -
in no key and seven keys. 481,696 names, byte-identical. The same rig run
against the previous Pro finds 1,231 differences, so it can see one.

## What it means here

The reader only labels chords in this script: suggestions are built from the
key, and the root it reads is shown, not used. So the visible effect is a
handful of names - imported suspended and quartal voicings, mostly, and the
altered dominants.

Midi Variator copies `ms_theory.lua` whole and Noterator vendors it; both are
updated from this commit.
